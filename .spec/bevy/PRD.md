- 依据 / Basis: `.spec/bevy/REQUIREMENTS.md` §9（用户确认"沿用横版跳跃类玩法"）、§10（SPIKE-2 裁决）、

## 1. 产品目标

在**全新空白工程**中，由 Planner→Developer→Tester 三角色流水线产出一个**可运行的横版跳跃小游戏**，
其关键行为能被**语义工具在游戏进程内观测并证实**（见 §4 可观测契约），而不依赖任何模型自撰的观测脚本。

## 2. 玩法需求（P1..P5）

| 编号 | 需求 | 验收落点 |
|---|---|---|
| **P1** | 玩家角色可**左右移动**，受注入输入驱动；松开输入后速度归零（不保留惯性漂移） | E3-① |
| **P2** | 场景中存在**可拾取的金币**；玩家接触后**金币计数 +1**（计数从 0 起） | E3-② |
| **P3** | 存在**终点/胜利条件**：玩家到达后**胜利标记由 false 变 true**（单向、不可回退） | E3-③ |
| **P4** | 玩家**能跳跃**：受注入输入驱动，起跳后**先上升后下降**，并最终回到地面 | E3-④ |
| **P5** | 玩家具有**接地状态**：站在地面时为真、离地（跳跃中）时为假 | E3-⑤ |

## 3. 可观测契约（游戏必须满足；违反即 E2/E3 不可判定）

> 依据 SPIKE-1/2：BRP 原生**没有**输入与截图动词；输入注入必须由游戏**声明可反射的意图面**；
> 语义状态必须可反射，否则适配器读不到。**类型路径（含 crate 名）即契约**。

**C1 插件与特性**：`bevy = { version = "0.19.1", features = ["bevy_remote"] }`；
`RemotePlugin::default()` + `RemoteHttpPlugin::default()`；**必须加 `ScheduleRunnerPlugin`**
（否则应用一帧后退出、端点从未绑定）；**同一二进制 + 运行时开关**支持无窗口无 GPU 运行。

**C2 可反射语义面（须 `#[reflect(Component/Resource)]` + `register_type`，且路径冻结）**：

| 语义 | 形态 | 约定（路径须写入 `contract.rs` 并冻结） |
|---|---|---|
| 玩家标记 | Component | 用于定位玩家实体 |
| 玩家位置 | Component（`Transform`） | 只读 `translation.x` / `translation.y`（**不得用数组下标**） |
| 接地状态 | Component | 布尔可读；E3-⑤ 依据 |
| 金币计数 | Resource | 整数，随拾取递增 |
| 胜利标记 | Resource | 布尔，单向 |
| 注入意图 | Event 或 Resource | **必须带命名字段**（单元结构体事件经 `observe+watch` **收不到帧**） |

**C3 注入语义**：注入面必须是**电平触发**的持续量，**边沿由游戏每帧自清**
（实测：每帧清零时 0.4 s 仅走 **2 px**，电平后 **92 px**）。

**C4 一致性**：语义读取**逐调用**；**不得**依赖 JSON-RPC batch 做一致性快照（batch **非帧原子**，
实测同一批相同调用返回中同时出现 coins:1 与 coins:2）。

**C5 状态不得藏在不可反射处**：关键状态**不得**仅存在于不可反射的引擎资源中
（实测 `bevy_time::time::Time` 不可读）。

**C6 无截图要求**：本 PRD **不要求**截图能力（用户已决定截图不纳入判据）；若将来需要，须另实现自定义 BRP 方法 `game.screenshot`。

## 4. 质量与边界

- **玩法规模**：一个小关卡即可（无需多关卡、无需美术资源、可用几何图元表示）。
- **启动**：headless 模式下进程须稳定运行 ≥ 单轮预算（不自行退出）。
- **不要求**：音频、菜单、存档、多人、关卡编辑器。
- **性能**：headless 下逻辑帧率须足以在数十帧内分辨跳跃的上升与下降（SPIKE-2 实测无窗口 60.3 FPS）。

## 5. 与验收判据的映射

本 PRD 的 P1..P5 逐条对应 `REQUIREMENTS.md` 的 **E3 五条观测**：
①位移改变 ②计数 0→N ③胜利位 false→true ④跳跃**兼有上升步与下降步**（单调下落不算）⑤**起跳前 Grounded 为真**。
E1/E2/E4/E5/E6 分别约束：真实工程增量、可构建可启动且门为绿、可复现且留全证据、QA 未改冻结快照、裁决诚实。

## 6. 明确不在本 PRD 范围

- Godot 时期工件（`PRD-mario.md`）继续作为**历史工件**保留，**不被本 PRD 修改或引用为运行时要求**；
- 旧 177 条 Godot 工具契约**不作任何名字映射**到 BRP 的 23 个动词。
