# PRD — Mario-like Platformer（HoH 的公开规格 S）

- 状态：**草稿 v1，待用户确认后冻结**
- 冻结后规则：文件只读；HoH 运行元数据记录其 SHA-256；轮次之间**不得修改**（对应 R11：S 是唯一权威需求源）
- 消费者：Project Planner（选优先级）、Developer（实现依据）、QA Tester（推导 checkable claims）
- 参照：Super Mario Bros. 1-1 式横版卷轴平台游戏的**玩法结构**（非美术、非关卡数据复刻）

---

## 1. 产品目标

交付一个**单机、单人、横版卷轴 2D 平台游戏**：玩家控制角色向右跨越地形障碍、躲避/消灭敌人、
收集金币，抵达关卡终点获得胜利；过程中可失败并可重新开始。

产品必须满足「**人类可玩**」这一标准：键盘输入有即时且可解释的反馈，状态变化在画面上可见。

## 2. 运行环境与工程约束

| 编号 | 约束 |
|---|---|
| P1 | 引擎：Godot 4.7.x（本机 mono 版）；2D 管线 |
| P2 | 项目必须能被 Godot 编辑器打开且**无脚本编译错误**；主场景可通过 MCP `play_scene` 启动 |
| P3 | 输入全部使用 Godot InputMap 的命名 action（至少 `move_left` / `move_right` / `jump`），以便用 MCP `simulate_action` 驱动 |
| P4 | 运行时状态可被外部观测：关键节点具有稳定且语义清晰的名称（供 `assert_node_state` / `get_game_node_properties` 定位） |
| P5 | 不依赖联网资源；首版可用程序化图形（ColorRect/Polygon/Godot 内置图元）作为占位，美术资产属后续增量 |
| P6 | 脚本语言：GDScript（不引入外部插件依赖，`godot_mcp_rs` 插件除外） |

## 3. 功能需求（每条都是 QA 可判定的 checkable claim）

### 3.1 玩家与控制
- **F1 移动**：按住左/右键，玩家水平位置持续变化；松开后停止（受摩擦影响允许滑行但必须最终静止）。
- **F2 跳跃**：按下 jump，玩家获得向上速度并离地；跳跃高度受重力限制；落地后必须能再次跳跃。
- **F3 朝向与动画状态**：玩家朝向随最后一次水平输入变化，且该朝向是可观测状态（节点属性或动画状态）。
- **F4 相机跟随**：玩家前进时相机跟随，玩家始终位于可视区域内。

### 3.2 地形与碰撞
- **F5 地面碰撞**：玩家不能穿越地面与砖块；可站立其上且不会下沉或抖动。
- **F6 实体阻挡**：撞墙时水平移动被阻挡，不发生穿模。

### 3.3 敌人
- **F7 巡逻**：至少 1 个敌人在平台上左右巡逻，碰到边界或墙壁后转向。
- **F8 接触伤害**：玩家从侧面/下方接触敌人会损失生命（或触发死亡流程）。
- **F9 踩踏消灭**：玩家从上方落下接触敌人时，敌人被消灭，且玩家获得向上弹跳反馈。

### 3.4 收集与方块
- **F10 金币**：金币被玩家接触后消失，且 HUD 金币计数 +1。
- **F11 问号方块**：玩家从下方顶击后产生可收集的金币或道具，方块进入「已使用」状态（不可重复产出）。
- **F12 可破坏砖块**：玩家从下方顶击后砖块消失（或碎裂），且不再阻挡玩家。

### 3.5 流程与状态
- **F13 胜利**：玩家抵达关卡终点标记后进入胜利状态，画面出现可见的结算结果。
- **F14 失败**：生命耗尽或掉落出关卡下边界后进入失败/重开流程，且该状态可观测。
- **F15 重新开始**：失败后可重新开始关卡，初始状态（位置、生命、金币）正确复位。
- **F16 HUD**：画面常驻显示至少生命、金币、时间（或分数）三项信息。
- **F17 关卡规模**：单次完整通关路径的预期耗时在 30–120 秒之间；关卡为横向单向推进（允许不回头）。

## 4. 非功能需求

- **N1 可启动性**：任何轮次的 `A_t` 都必须保持「可启动」——不允许留下会让项目无法运行的中间状态（对应论文「keep the project buildable and runnable」）。
- **N2 可观测性**：每条功能需求的实现都必须能通过公开手段观测（键盘输入 + 截图 + 运行时节点属性/回放记录），不接受只能从源码推断的实现。
- **N3 稳定性**：连续运行 60 秒不崩溃、不出现脚本运行时错误刷屏。
- **N4 保持性**：已被验证的功能不得在后续增量中静默回归。

## 5. 首版明确不做（防止范围蔓延）

- 多关卡、关卡选择、存档、暂停菜单（暂停可作为后续增量）
- 音乐/音效（音频属后续增量）
- 外部美术资源、AnimatedSprite 精细动画
- 道具系统（蘑菇/火球/无敌星）、Boss、隐藏区域
- 手柄支持、触屏支持、移动端导出
- 3D、多人、联网

## 6. 验收口径（供 QA Tester 推导 claims）

QA 必须**从本文件与当前开发文档 D_t 推导** checkable claims，并为每条给出：
- 公共执行记录（MCP 回放 trace / 截图路径 / `assert_node_state` 结果 / 运行时属性快照）
- 状态：`verified` 或 `gap`
- gap 必须附 `player_impact` 与 `recommended_update`

**判定纪律**：
- 仅凭源码中存在某段逻辑，**不构成**行为验证；
- 观测不到的行为一律计入 gap，禁止推断为成功；
- 回归（此前 verified、本轮复现失败）必须作为独立 gap 记录，并说明其历史验证来源。
