- **必须 fail-closed**：标记来源**缺失/不可读/格式非法**时 ⇒ **拒绝推送**并打印原因。
- 必须正确解析 `pre-push` 的 **stdin 协议**（`<local ref> <local sha> <remote ref> <remote sha>` 每行一组），
  对**每一个**将要推送的提交范围（`<remote sha>..<local sha>`）判断；**已被远端包含的提交不重复判断**。
- 允许的情形：**待推送范围内每个提交都被标记为"已验收"**；
  **删除分支/无新提交**（`local sha` 全 0）等边界必须**明确处理**（写清选择与理由）。
- 拒绝时输出**可操作**的信息：哪些提交未被标记、**如何标记**、以及"这是硬约束，不得用 `--no-verify` 绕过"的提示。

- **必须支持"标记内容含验收报告路径与结论（pass）"**，使"提交 → 验收报告 → 推送"可互查。

### ④ 测试（**离线**；只对本地裸仓推送，绝不碰真实远端）
- 在临时目录建一个 **bare 仓库**作为 `origin` 替身；把钩子与标记机制在**真实 git 流程**下走通：
  1. **未标记 ⇒ 推送被拒绝**（断言非 0 退出 + 拒绝原因文本）；
  2. **标记后 ⇒ 推送成功**；
  3. **已被远端包含的提交**不会被重复判断（例如第二次推送为 no-op 且不被误拒）；
