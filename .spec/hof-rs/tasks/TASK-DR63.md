## 0. 四项（都由独立验收实测，非猜测）

1. **清单是角色可写的 ⇒ 判据权威性未强制**：任何角色都能在**被拷贝的目录**里写 `.superseded.json`，
   使**本轮甚至同伴角色**的产物被判"已取代"而**不进候选视图**。验收者的 P1 正是 Developer 自己写的清单触发了跳过。
   （**不是回归**：旧的名字判据同样由角色自选名字触发；但**现在必须做对**。）
2. **清单损坏 = 硬错误**：`SupersededSet::load` 对不可解析内容返回 `InvalidData` 并**上抛** ⇒ `copy_tree`/`copy_evidence`
   **视图构建失败** ⇒ 角色可（有意或无意）**让一整轮失败**。
3. **判据是逐精确路径而非逐子树（info）**：把一个**目录**记进清单**不会**抑制其中内容
   （`is_superseded` 对子项返回 `false`）。当前无生产路径记录目录（`invalidate_artifact` 只处理 `is_file()`）。
4. **拷贝开销未测**：`is_superseded` 对**每个条目沿路径分量逐级 `exists()`+读取**；`copy_tree` 现在**每文件**都走一遍。
   测试规模无感，**大工作区未测**。

## 1. 要做的事

1. **权威性**：让"谁有权声明取代"**可判定**——例如清单只由**生产侧**（受信写入点）写、或对**角色写入**做
   来源校验/签名/受限路径，**或**把清单移出"角色可写且会被拷贝"的目录集合。**必须**有一条测试证明
   *"角色写下的清单不能把**本轮/同伴**产物判为已取代"*（先红后绿）。
   **若你判定"限制角色写入不可行"，停下来上报并给出方案对比，不要假称做到。**
2. **损坏降级**：清单不可解析时**不得**让整轮失败——改为**忽略该清单并告警**（写进运行的 warnings/日志），
   或**隔离该清单**。**必须**有测试：畸形清单 ⇒ 视图**仍能构建**，且**有可观测的告警**。
   （注意：**不得**因此放宽 DR-62 的"被取代者不进候选"的既有断言。）
3. **子树语义**：让 `is_superseded` 对"被记录的**目录**"**覆盖其子树**（或**断言目录永不被记录**，并给出理由）。
   二选一，**说明你为何选它**，并给出对应测试。
4. **开销**：测量 `copy_tree`/`is_superseded` 在**大目录**（例如你构造 1e4 个文件、多层嵌套）下的墙钟，
   与朴素基线对比，把**真实数字**写进报告；若开销显著，给出**一次遍历内的缓存**（同一轮内对同一清单只读一次）。
