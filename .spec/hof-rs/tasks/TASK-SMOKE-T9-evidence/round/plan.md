## Project Planner Priorities
### Priority Order
1. **Launchable, error-free project (blocker)** - The Godot 4.x project opens and `res://scenes/main.tscn` boots via MCP `play_scene` with mode `main` and zero script compile errors; `editor_get_errors` returns an empty errors list, the scene tree exposes the stable nodes `Player`, `Ground`, `Enemy1`, `Coin1`, `HUD` and `Goal`, and the InputMap actions `move_left` / `move_right` / `jump` are drivable by `editor_simulate_input_action` against the game process (observable outcome: `running_game_get_scene_tree` lists those named nodes and the input channel probe reports `GAME_INPUT_CHANNEL_OK`).
2. **Player movement, jump and collision (F1-F3, F5-F6)** - Holding `move_right` moves `Player` right and releasing stops it; pressing `jump` gives upward velocity so `Player.position.y` decreases, gravity brings it back, and a second jump works after landing; the player cannot pass through `Ground` or a wall (observable outcome: `running_game_get_node_property_samples` on `Player.position` shows changing x while the action is held, a negative-y delta on jump, and a stable y while standing on `Ground`).
3. **Minimal end-to-end loop: coins, win and HUD (F10, F13, F16)** - Touching `Coin1` removes it and increments the HUD coin counter; reaching `Goal` triggers a visible win state; the HUD always shows lives, coins and time (observable outcome: a screenshot after pickup shows the coin gone and a higher HUD count, `assert_node_state` reports the win flag, and the HUD `Label` text is non-empty).
### Preservation Gate
- Launchability must not regress: after every change the project still opens with no script compile errors (`editor_get_errors` empty) and `play_scene` boots `res://scenes/main.tscn` (P2, N1).
- The InputMap actions `move_left`, `move_right` and `jump` stay bound in `project.godot` so MCP `simulate_action` can drive them (P3).
- Scene integrity must not regress: exactly one root node in `scenes/main.tscn` with every parent path resolving, and every physics body plus the `Goal` area keeping a non-empty collision shape (P4, F5, F6, F13).
- Iteration 1 has no verified_records in `.hoh/evidence.json`, so no previously verified behaviour is at risk; the launchability and observability baseline above is what this iteration must preserve.
### Acceptance Gate
- Smallest end-to-end validation: run `play_scene` on `res://scenes/main.tscn`, confirm `editor_get_errors` is empty and the scene tree contains the named nodes, then simulate `move_right` and `jump` and capture `Player.position` samples proving x changes and y rises then falls, and capture a screenshot showing the HUD label with lives, coins and time, with no script runtime error during the run.
