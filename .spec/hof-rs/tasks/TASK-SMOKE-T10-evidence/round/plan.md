## Project Planner Priorities
### Priority Order
1. **Launchable observable baseline** - Keep res://scenes/main.tscn as the main scene and make it start via MCP play_scene with zero GDScript compile or runtime errors; expose stable semantically named nodes (Player, Ground, Enemy, Coin, CoinLabel, LivesLabel, Goal) so assert_node_state and get_game_node_properties can locate them. Observable outcome: play_scene returns a running scene and a property snapshot of Player plus the HUD labels can be read back.
2. **Player movement jump and camera** - Wire the named InputMap actions move_left, move_right and jump so MCP simulate_action drives them: held horizontal input changes player position and release settles to rest, jump produces upward motion and a later landing, facing and grounded state are readable node properties, and the camera keeps the player inside the visible area. Observable outcome: before and after position snapshots around simulated input plus a screenshot showing the player visible while moving right.
3. **Core interaction loop** - Make the smallest full playable loop observable: touching a coin removes it and increments the HUD coin count by exactly one, side or bottom enemy contact costs a life or starts the death flow, falling below the level bottom triggers failure, reaching the Goal node enters a visible victory state, and restart resets position lives and coin count. Observable outcome: coin and lives label values change in runtime property snapshots and a screenshot shows the visible victory result.
### Preservation Gate
- The project must keep opening and running: res://scenes/main.tscn remains the main scene, the scripts under scripts/ stay free of compile errors, and the InputMap actions move_left, move_right and jump remain present with their current key bindings.
- No previously working behavior may regress; iteration 1 has no verified QA records, so the existing project structure (project.godot settings, main scene, existing scripts) is the launchability baseline that must still start cleanly after changes.
### Acceptance Gate
- End-to-end: launch res://scenes/main.tscn via MCP play_scene with no script errors, simulate move_right and confirm the Player position changes while the camera keeps the player visible, then simulate jump and confirm the player leaves the ground and lands again; capture screenshots plus a runtime property snapshot (player position, facing, lives, coin count) as evidence and keep the scene running for 60 seconds without crashes or error spam.
