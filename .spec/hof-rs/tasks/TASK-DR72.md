### ①（一级）**脱敏器写坏 JSON 轨迹** —— 根因已定位，须真正修好
`src/runtime/secrets.rs:70-98` 用 `find([';','\n','\r'])` 定位被脱敏值的结尾，**不识别 JSON 转义的 `\n`**；
当赋值出现在 JSON 字符串内且**后随物理换行**时，它会**吃到物理行尾**，删掉**字符串其余部分、闭引号与逗号**
⇒ `runs/smoke-t10/iter-1/traj/tester.attempt1.json` **成为非法 JSON**（char 412870，正是 `HOH_MODEL_API_KEY=<redacted>` 处）；

**要做**（三选一并说明理由，**必须覆盖"转义 `\n`"这一形态**）：
- **(a) 修匹配**：把 `\n`/`\r`（转义序列）也纳入值尾判定；
- **(b) 结构化改写**：`parse → 改写 → serialize`，**绝不按字节猜边界**；
- **(c) 改写前先验证**：**先确认目标可解析**，改写后再验证**仍可解析**；**不可解析则不改写并显式报告**。
**测试（先红）**：
- 一条**对抗性测试**：把 `KEY=<val>` 放进 **JSON 字符串内**并让其后随**物理换行** ⇒ 断言**改写后仍是合法 JSON 且其余内容逐字节不变**（当前必红）；
- **通用不变量**：**凡被脱敏的文件，改写前后都必须是"可解析的 JSON（若是 JSON）"**，且**除被替换的字节区间外逐字节相同**（给出可复核的差分方式）。
