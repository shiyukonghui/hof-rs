## 1. 目标（三块）

### A. 把两种失败**分开测量**（口径修正，本任务先做）
1. **新增"脚本化玩家"臂**（`--player=scripted`）：定义一个**确定性、人样**的策略（按游戏声明动作做合理动作序列，
   例如 pong 交替跟踪球、snake 转向吃食物、tetris 左右+落），用它测**游戏侧可玩性**：
   对局时长 / 存活步数 / 玩法推进步数 / 是否出现动态变化。→ **这才回答"游戏能不能玩"**。
2. **保留"模型玩家"臂**（`--player=jev|playjev`）回答"模型能不能玩"。
3. 报告里**两条臂并列**，并在 Z3 那类指标上明确"哪个是游戏问题、哪个是模型问题"。

### B. 让模型真的玩起来（本任务核心；≥4 个**声明式**变体，逐一给结果）
对 **pong / snake / tetris**（+ 有余力再加 game2048）逐款跑下列变体，**每个变体都要给逐字 request/response 与结论**：
* **V1 基线**：现状（仅图像 + 单一 `choice` 问句）。
* **V2 图 + 结构化 state**：`/v1/systemone` 允许 `state` 与 `image` **同时**给（图像请求仍是 1 图 1 问），
  把**可读状态**（球/挡板/蛇/棋子的关键量、上一动作与其结果、比分）写进 `state`，图像照给。
* **V3 问法与候选描述**：把 `criteria` 的每个候选写成**"这个动作会怎样改变画面/状态"**（而非只有名字），
  问句改为"**现在做哪个动作能推动游戏**"。保留逐字原文。
* **V4 反重复**：当上一步动作**未产生变化**时，把它**显式写进 `state`**（"上一步 X 没有产生任何变化"），
  并在候选里**排除**它（或降权），再问一次；记录是否因此脱离固定点。
* **V5 图像形态**（有需要才做）：全尺寸 800×600 / 裁剪游戏视口 / 降采样，记录用的是哪种。
* 每个变体给：**步数、玩法推进步数、固定点是否触发、失败步的判据明细**；
  并回答一个明确问题：**模型是"没在看图"还是"看了但选不动"**（用"同一状态换图/换问法是否改变答案"来判）。

### C. 修固定点判据（现有实现有盲区）
1. **`MODEL_NO_PROGRESS`（新）**：连续 **≥3 步**即使**动作不同**也**无玩法推进** → 报此结论
   （`pong × playjev` 那种"混了一次不同动作"的情况必须被它抓住）；
2. **`MODEL_FIXED_POINT`（保留）**：连续 ≥3 步**同一动作且同帧**；
3. 两者**都不算游戏缺陷**、**都不得**用于判游戏 PASS；在 `gate.json` 与报告里**分开记**；
4. `tools/tests/test_playability_model_player.py` **增加断言**：构造"混了不同动作但无推进"的序列 → **必须**判 `MODEL_NO_PROGRESS`；
   构造"同动作同帧" → 判 `MODEL_FIXED_POINT`；构造"有推进" → 两者都不触发。
