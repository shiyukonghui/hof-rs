# 任务书目录（`recovery/tasks/`）

本目录是**决策者 → 子代理**的唯一交接通道。约定（2026-09-27 起，用户指示）：

1. **决策者只写任务书**：每批工作开工前，任务书写成 `TASK-<编号>.md` 放在本目录，**自包含**
   （背景、目标、范围、硬性约束、验收判据、证据要求、报告落点）。任务书里出现的每个事实都应
   自带出处或可复现命令，不依赖会话上下文。
2. **子代理只读任务书**：派发时的提示极短——"读 `<绝对路径>` 并执行"。子代理不再从提示里
   接收任务内容。
3. **子代理只回报告路径**：完成后把报告写成 `recovery/reports/TASK-<编号>-REPORT.md`，
   返回值就是该**路径**（外加必要的一两句状态），不再回长结构化摘要。
4. **验收同样走任务书**：独立验收的任务书写 `TASK-<编号>-ACCEPT.md`，报告写成
   `recovery/reports/ACCEPTANCE-TASK-<编号>.md`，同样只回路径。
5. 任务书与报告都**入库**（`recovery/` 非大块产物部分），使"决策 → 执行 → 判定"三件套可互查。
6. **文件所有权（并行必须遵守，2026-09-27 增补）**：同一时刻只允许**一个**子代理写某个文件。
   因此在任务书里必须显式写出该批**独占的文件清单**与**禁止触碰的清单**；两条并行任务书
   不得把同一个文件列进各自的独占清单。
   * 事故记录（TASK-127/128 并行）：`tools/playability_gate.py` 被两边同时改，导致 TASK-127
     提交时把 TASK-128 未提交的 `--base-url` 本体一并提交，只能靠提交信息逐字声明来补救。
   * 由此追加两条：①并行任务开工前先在任务书里对齐"谁改哪些文件"；
     ②提交前用 `git status --short` 确认**只有**自己独占清单里的文件被暂存；发现别人的改动**不要替他提交**，
     改为在报告里点名并留给对方。
7. **任务书里的事实必须标注来源等级**：一手（仓库代码/模型卡原文，带路径或 URL）与二手（文章摘要、
   第三方复述）必须区分。TASK-127 实测证明：任务书里两条二手事实（`abstain` 字段、`state.frames`）
   与 `playjev/serve.py` 真实代码不符——**子代理应以代码为准并显式纠正任务书**，这一行为被鼓励，不是抗命。
8. **严格单线程（2026-09-27 用户最终指示；推翻同日早先"并发用 worktree"的方案）**
   * **同一时刻只允许一个子代理在改本仓。** 决策者必须**等到上一个子代理交出报告路径**，才能派下一个。
     不允许"为了快"并行派发。
   * **理由（不是偏好，是踩过的坑）**：并发已经造成两次实际损害——
     ① TASK-127 与 TASK-128 **同时改 `tools/playability_gate.py`**，导致 TASK-127 的提交把 TASK-128
     未提交的 `--base-url` 本体一并带走，只能靠提交信息声明补救；
     ② 并发还需要额外机制（分支隔离、被忽略重目录的联接、清理顺序、端口/GPU 不隔离）来兜底，
     而这些机制本身又引入新风险（例如 `Remove-Item -Recurse` 会**穿过联接删掉目标内容**）。
     用户裁定：**稳定性 > 吞吐**。
   * 因此：**不使用 git worktree、不为并行开分支**；所有改动串行落在主工作区与 `master` 上。
   * 串行下仍然保留三条纪律：
     ① 任务书里照旧写"**独占文件清单**"与"**禁止触碰清单**"（现在是边界自查，不是并发协调）；
     ② 提交前用 `git status --short` 确认**只暂存自己独占清单里的文件**；
     ③ 若发现**上一批遗留的未提交改动**（例如别人写的文件）→ **不要替他提交**，在报告里**点名**留给决策者裁决。
   * 引擎仓（`godot-mcp/godot/`，自带 `.git`）也是共享的：**同一时刻只有一个任务可以改引擎模块**。
   * **附录（只作知识留存，不启用）**：万一将来用户明确批准并发，唯一可行做法是 git worktree（一任务一分支）
     并把被 `.gitignore` 的重目录用**目录联接**接回主工作区；已知坑：新 worktree 里**没有**引擎克隆/`runs/`/`dist/`/`models/`、
     联接**不能**指向 `.git`、`Remove-Item -Recurse` 会穿联接删目标（清理必须先 `rmdir` 删链接再 `git worktree remove`）、
     **端口与单块 GPU 不被 worktree 隔离**（仍须逐个预留端口与串行调用模型）、引擎仓仍是同一个。
     **启用前必须得到用户明确批准。**
