## 0. 被验收的判据（用户口径，验收基准）

1. **Jev 当模拟真人玩家**：模型**看图**输出一个操作 → 脚本注入游戏 → 记录画面变化。
2. **FAIL（用户点名的"问题"）**：**模型输出了操作 ∧ 游戏确实接受了该输入 ∧ 画面没有动态变化**。
3. **PASS**：连续 ≥8 步里"接受 ∧ 画面变化"的比例 ≥ **75%**，**且**子代理**读前后图**判定这些变化**符合游戏逻辑**。
4. **`strict` 余量**：变化必须 **≥2× 同帧预算的零输入对照窗** 且 ≥1.0（`baseline` = 裸 `>` 仅作对照）；
   **只有 strict 通过才算 PASS**；仅 baseline 通过者写 **`PASS(baseline only)`** 且 **`counts_as_pass=false`**。
5. `MODEL_FIXED_POINT` / `MODEL_NO_PROGRESS` 是**测量侧**结论，**与 FAIL 分开**、**不得**用于判游戏 PASS。
6. **子代理必须读图**：逐帧 `read_image` 并写下"看到了什么 / 变了什么 / 是否符合游戏逻辑"；**数字不得冒充看图**。
7. **P1–P7 只用于"确保代码能跑"**，不用于可玩性判定。
