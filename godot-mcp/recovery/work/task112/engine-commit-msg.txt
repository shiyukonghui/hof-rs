fix(mcp_server): TASK-112 - the three engine defects TASK-111 registered are fixed at the root (one of them blocking and silent), plus one schema override

D-T111-1 (blocking, silent wrong result). `publish_file_atomically()` saved a
resource into `<name>.mcp-tmp.<ext>`; the engine's own `ResourceSaver::save()`
callback then ran for THAT path
(`core/io/resource_saver.cpp:146-148` -> `EditorNode::_resource_saved`,
`editor/editor_node.cpp:7963-7974` -> `EditorFileSystem::update_file`), which
registered the UID the text saver had just minted for the scratch name
(`ResourceUID::add_id(uid, scratch)` + `update_cache()`). The rename that
published the file changed the file NAME and nothing else, so
`.godot/uid_cache.bin` kept `uid -> <name>.mcp-tmp.<ext>`. A scene referencing
that resource by UID then resolved it to a file that does not exist
(`resource_format_text.cpp:481-483` prefers the UID over the still-correct
`path=`), `ResourceLoader::_load_start` returned a null token and the load died
with "[ext_resource] referenced non-existent resource" - with the write tool
exiting 0 (measured in TASK-111 section C2 on projects/_exercises/ex_3d).

Fix: `MCPTools::retarget_published_uid(p_path)`, called by the module's ONE
publish primitive after a successful rename, so scene/resource/theme writers
all get it from one place. It reads the UID from the published file's own
header (the authority in the editor; `ResourceLoader::get_resource_uid` only
reads headers under `is_editor_hint()`, `resource_loader.cpp:1412-1426`) and
falls back to the mapping the save callback registered for the scratch name
(`ResourceUID::get_path_id`, which is only usable in non-editor processes -
`main.cpp:2255-2257` enables the reverse cache there). It then re-points the
forward map at the destination (which is what `uid_cache.bin` is written from)
and persists with `ResourceUID::update_cache()`, guarded by
`is_editor_hint()` plus "the project data directory already exists".

The alternative that looks more canonical - `EditorFileSystem::update_file()`,
the very call the engine made with the scratch name - was implemented first and
MEASURED to crash the full `--test` run: that singleton exists in the test
process but is not usable there, and the crash does not appear in the
`--test-case=[MCPServer]*` subset. `update_cache()` is the primitive
`update_file` itself ends up calling and is safe in every process.

Rejected fixes (DECISIONS.md D157): making the scratch name non-registrable
(the format saver requires the extension to stay last - already measured at
`tool_helpers.h:139-146`), and bypassing `ResourceSaver` with `FileAccess`
(that would mean re-implementing Godot's serialization formats).

D-T111-2. `editor_add_resource_to_node_property`'s `resource_properties` bag ran
`property_value_from_json` -> `coerce_to_property_type` and skipped
`shape_vector_from_json`, the one step that folds a JSON object naming a
vector's/colour's components into that vector. So the tool refused
`{"size":{"x":48,"y":48}}` for a `RectangleShape2D` with `-32602` (measured,
TASK-111 `c4-040`) - with a message that told the caller to send exactly that
shape - while the sibling `editor_setup_collision_shape` and both
`project_*resource` writers accepted the identical input.

Fix: the loop now calls the module's exported, shared bag writer
`MCPTools::write_resource_properties` (TASK-049 exported it for this reuse), and
the answer gains the same read-back fields the sibling writers answer
(`properties_set` / `ignored` / `ignored_count` / `changed`) instead of an
unconditional success. This is a declared behaviour-surface increase.

D-T111-3. `editor_add_raycast`'s `dimension` was not validated at all
(`dimension == "2d" ? RayCast2D : RayCast3D`), so `"4d"`, `"2D"` and typos all
silently built a `RayCast3D` while the answer echoed the caller's spelling back
(measured, TASK-111 `c4-033`: `{"dimension":"4d"}` -> `{"added":true,
"type":"RayCast3D"}`). It is now a closed set, decided BEFORE the editor guard,
so a game process and a doctest both see the refusal.

Contract: `SCHEMA_OVERRIDES["add_raycast"]` declares
`enum:["2d","3d"]` (mode=replace, every other member verbatim, `required` stays
`[]`), generator 1.22.0 -> 1.23.0, `_meta.overrides` +1. The regenerated
contract's structured diff is exactly three things: `dimension.enum`, the
generator version and the one override record.

Doctests added (all in `tests/test_mcp_server.h`):
  * "a published resource's UID ends up on the published path, never on the
    scratch sibling" - reproduces the editor's registration, publishes the file
    the way every writer does, asserts the UID now names a path that EXISTS, and
    loads back a scene that references it by UID. Red before the fix (the UID
    still named `...mcp-tmp.tres`), green after.
  * "the resource-properties bag folds a component object into its vector" -
    pins the two primitives around the missing line plus the shared writer, for
    a Vector2 AND a Color property, and keeps the "a component that cannot fill
    its slot is still -32602" gate. It uses `StyleBoxFlat` rather than
    `RectangleShape2D` because `Main::test_setup()` never calls
    `PhysicsServer2DManager::initialize_server()` while `Shape2D()`'s
    constructor needs the physics server - `memnew(RectangleShape2D)` is a
    measured SIGSEGV in the doctest process.
  * the existing argument-validation case gains the three `dimension` refusals
    (`"4d"`, `"2D"`) and a positive control that `"2d"`/`"3d"` are not refused
    by the dimension rule.
