modules/mcp_server: task098 - MCP-TRACEABILITY section 7 is aligned with the D-1 closure

Section 7 was written while D-1 was still open, and its conditional wording made a
closed defect read like a current one. This is a doc-only change; no module byte is
touched, so nothing is rebuilt.

* a closure banner: D-1's root cause is tool defect D-3 and it was fixed at the root in
  TASK-097 (editor_add_nodes_batch refuses a name the target parent already carries by
  default, with the complete conflict list, and editor_save_scene reports what an
  explicit rename leaves behind); the three older scenes' duplicate layers were deleted
  and the pixel column was refilled with real numbers (Pong 14/74, Breakout 14/89,
  Snake 13/102, independently recomputed). "unavailable (D-1)" is therefore the
  historical record of the runs before the cleanup, not the current state.
* the duplicate-count table now reads 8/20/37 and carries the reason TASK-096 wrote
  5/18/37: those were the @ColorRect@-only counts. The pre-cleanup scene text the
  cleanup session itself read back is quoted (5+3, 18+2, 37+0, scene bytes
  3391/8553/13284 matching TASK-097's pre-cleanup sizes), with the recount script named.
* a new section 7.3 writes down the four conditions under which section 7 still applies
  (a clean scene, something that actually moves, a number that carries its own control,
  and the right --pixel-evidence setting) and the three boundaries that keep it from
  being read as a promise that pixel evidence is always available.
