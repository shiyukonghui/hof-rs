feat(godot-mcp): TASK-120 (D164) - tighten the readback witness rules, cross-check channel vs verb, and give the 17 boundary-less tools a real refused call (batch c8)

TASK-119's independent acceptance failed the ledger on the witness mechanism,
and this is the fix (decision record: DECISIONS.md D164).

A) verify_readback() now enforces four hard rules, each rejection carrying its
   own reason in the ledger's rejected list:
     A1 the witness tool must be a READ-verb tool (and not the witnessed tool);
     A2 the accepted witness call must come AFTER at least one call of the tool
        it witnesses (same run, larger seq) - a read taken before the write can
        only report the pre-write value;
     A3 at least one `expect` literal must carry a VALUE - a bare JSON key name
        ("position") is refused, because every payload of that reader matches it;
     A4 `expect_absent` may not be declared without an `expect` subject anchor.
   All 51 declarations were re-judged: 14 were unqualified and are repaired with
   values taken from the witness payload itself (0 downgraded, 37 unchanged).
   The three input-recording tools now use real read calls with post-write
   values; the recorder exposes no read tool of its own, which the manifests say
   out loud.

B) load_channels() refuses to run when a channel contradicts the tool's verb:
   an action verb may not declare `payload` (read_payload only accumulates for
   read-verb tools, so that evidence gate could never be satisfied -
   os_deploy_to_android_device, verb deploy), and a read verb may not declare a
   screen/file/memory channel (its answer IS the measurement -
   editor_capture_screenshot, capture is a READ_VERBS member). Both declarations
   are fixed, with their basis rewritten.

C) Batch c8 (tools/sessions/_exercises/ex_bound/, run c8-task120, ports
   9905/9906, session dual-parsed by Python and PowerShell 5.1 first) gives each
   of the 17 tools that had channel evidence but no boundary call exactly one
   same-shape refused call: one undeclared argument, refused by the registry gate
   at tool_registry.cpp:812-855 before the handler runs. No threshold moved:
   达标 from the refreshed ledger is 152 -> 169 and 计数达标缺证据 20 -> 3
   (177 = 169 + 3 + 5), and excluding the batch puts it back at 152/20.

D) Labels: the ledger header now prints the distinct-tool count it computes
   (172, not the 171 that was claimed in prose); needs_an_external_device lists
   each tool's own status instead of implying all three are unmeasurable; the
   engine_not_implemented class is registered for editor_set_auto_dismiss_dialogs
   (5 valid-input calls all answer -32000 Not implemented; the other 2 are
   argument-validation refusals); tool_channels.json declares that `basis` is a
   channel-level template.
