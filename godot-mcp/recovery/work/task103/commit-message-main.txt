feat(godot-mcp): TASK-103 (D151) - tool defect X-1 is fixed at its root and both engine variants are rebuilt at the module commit, and the 16th and 17th C# games are delivered through MCP calls only

A) X-1 (the only module change of this task). A GDScript body that compiles and then
fails while it runs used to answer ok + {"result":null,"result_type":"Nil"} with no
error code, no message and no suggestion, while the engine's stderr carried the whole
SCRIPT ERROR line - measured in TASK-102, where the ok answer was the only signal in
the response and it pointed the wrong way. The fix uses the engine's own error handler
(the hook the parse capture already uses): GDScriptFunction::call() reports the aborted
frame through _err_print_error(..., ERR_HANDLER_SCRIPT) at gdscript_vm.cpp:3988, and the
window is exactly one Callable::callp. The refusal is -32000 (tool_state) with
data.script_error (the engine's message, the line of 'code', the generated line, the
script path, the blamed GDScript function, the error count and every message) and
data.suggestion; a successful body that returned null now carries a note. The code is
-32000 and not -32602 (the body compiled) nor -32603 (this module is not what failed).
The generated script's identity is reconstructed the way GDScript makes it
(gdscript://<instance id>.gd) instead of read from Script::get_path(), which answers the
usually-empty path cache. The description and its C++ literal are regenerated through
the generator's append-only override, with the contract's six shape quantities unchanged
(177/6/1.22.0/154/73/idempotent, sha bd68e804). One new doctest pins the three
situations apart plus the push_error control; module cases 156 -> 157. The minimal
same-batch reproduction is the same six-call session run unchanged twice
(runs/match3/task103-x1-before vs -after), and the error now also reaches the trace call
line as error_data_json.

B) Two games, both written through MCP calls only, both with a second Python
implementation of their own rules whose outputs are the session's assertion literals,
both replaying the D-3 duplicate-name batch for its -32000 refusal, both with a
float-accumulator clock and two single-writer increment properties, and both sampling
with a must-move assertion that FAILS if the world is frozen.
* Tower Defense: a 16x12 grid of 50-pixel cells with a 101-cell branch-free serpentine
  corridor whose order is DERIVED from an ASCII map by a deterministic walk, integer
  travel, tower placement with four named refusals, towers with Chebyshev range 3 and a
  cooldown that pick the furthest-along enemy, three waves, lives and a win/loss pair.
  A whole game (three towers, 306 steps, 15 kills, 0 leaks, 5 lives, score 150) is
  predicted step by step in Python and asserted against the payload.
* Missile Command: six cities and three batteries with per-wave ammo, a linear
  congruential spawn generator, a floor-division trajectory spelled out identically in
  both languages, interceptors launched from the nearest loaded battery, explosions that
  clear the missiles inside a 34-pixel radius in index order, incoming missiles that
  destroy the cities within 28 pixels of their target, waves and scoring. One
  interception is AIMED by arithmetic: Python iterates the lead to a fixed point so the
  explosion forms exactly where the missile will be.
